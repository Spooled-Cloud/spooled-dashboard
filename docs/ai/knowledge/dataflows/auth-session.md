# Auth session

1. Login: API key → `POST /api/v1/auth/login` or email OTP (`LoginPage`, `src/lib/api`).
2. Zustand persist: access token in localStorage; refresh token memory-only (`src/stores/auth.ts`).
3. `AuthGuard` hydrate/refresh; admin separate `/admin/login` with `X-Admin-Key` (`src/lib/api/admin.ts`).
4. HTTP client attaches Bearer + `X-Organization-ID` (`src/lib/api/client.ts`).
5. Persisted org (`auth-storage`, zustand `version: 1`): `toPersistedOrganization` (`src/stores/auth.ts:34-38`) keeps `settings` as `{}` and drops `billing_email`, so the stored org has no webhook token. It runs in `partialize` (`auth.ts:206`). `migrate` (`auth.ts:217`) scrubs copies older versions wrote, and zustand rewrites storage after migrate. The in-memory org stays complete.
6. Runtime config first. `loadRuntimeConfig()` (`src/lib/config/runtime.ts:167`) is the only loader and caches the result. `getApiUrl()` and `getWsUrl()` (`runtime.ts:240`, `:247`) return defaults until it loads, and the API client does not wait by itself. The callers gate it: `RuntimeConfigBootstrap` wraps the protected, admin, login and onboarding shells (`src/components/providers/RuntimeConfigBootstrap.tsx:24-51`), hydration waits before `/auth/me` (`src/stores/auth.ts:272`), and the socket waits (`src/lib/websocket/client.ts:333`). On a hosted origin a failed `/api/config` throws instead of falling back to the hosted default (`runtime.ts:185`; `shouldAllowRuntimeConfigFallback`, `:41`).
7. Hydration (`auth.ts:251-283`): localStorage hydrates synchronously, so `persist.hasHydrated()` is checked at once and the expiry and missing-context checks run then. `onFinishHydration` is kept only for async storage (`auth.ts:279-283`). An expired token clears auth. A valid token without user or org context fetches `/auth/me`, but only after `loadRuntimeConfig()` resolves (`auth.ts:272`).
8. Trend history (`src/lib/hooks/useDashboardTimeseries.ts:157-176`) is stored under `spooled_dashboard_timeseries:<org>:<api_key_id>` (`src/lib/hooks/timeseries-storage.ts:13-15`). With no known scope nothing is read or written, and a scope change reloads that scope's history. `clearAuth` (`auth.ts:97-103`) removes the scoped key, the legacy unscoped key and any other `spooled_dashboard_timeseries*` key (`timeseries-storage.ts:18-30`). Logout always ends in `clearAuth` (`auth.ts:194`).
9. Socket close codes: 1008, 4401 and 4001 mean the session ended (`isAuthCloseCode`, `src/lib/websocket/client.ts:46-48`). The socket sets `auth_failed` and notifies the auth listeners (`client.ts:523-527`). `recoverFromRealtimeAuthFailure` (`src/lib/websocket/hooks.ts:65-83`) then probes `GET /auth/me`. A 401 runs the API refresh path: a new token reconnects through the hook, and a failed refresh clears auth so AuthGuard routes to login. A valid session reconnects after 5 s (`hooks.ts:18`). Every other close reconnects with backoff (`client.ts:529-535`), including the 1000 close the backend sends at its 1 h maximum connection age (`spooled-backend/src/api/handlers/realtime.rs:43` sets 3600 s, applied at `:784`; close frame at `:573`).
10. Socket lifecycle (`src/lib/websocket/client.ts`): `connect()` opens nothing until the config is loaded (`:333-337`). If the config fails, the state becomes `degraded` (`connectAfterConfig`, `:353`). The URL is `getWsUrl()` (`:213`). `/api/config` derives it from `PUBLIC_API_URL` (https to wss, http to ws) when `PUBLIC_WS_URL` is unset (`src/pages/api/config.ts:93`, `:145`). A Ping with no frame back within 10 s drops the socket (`pongTimeoutMs`, `:42`; `:576-594`). Token changes and manual retries go through `discardSocket` (`:254`), so a late close from the old socket cannot null or reopen the new one. After 20 failed attempts (`maxReconnectAttempts`, `:39`; check at `:606`) the state stays `degraded` until a manual retry.
11. Retries: mutations never retry (`mutations.retry: false`, `src/lib/query-client.ts:46`). Queries retry only transient failures: `shouldRetryQuery` (`query-client.ts:17-22`) never retries a 4xx and otherwise stops after `MAX_QUERY_RETRIES` = 3 (`:10`). The API client's only replay is after a 401 and a successful single-flight refresh (`src/lib/api/client.ts:219-231`).
12. Return path (`src/stores/return-path.ts`): `rememberReturnPath` (`:11`) keeps path, query and hash before auth is cleared or a protected page redirects. `consumeReturnPath` (`:29`) returns same-origin destinations only. Callers: `AuthGuard.tsx:71,173`, `auth.ts:172,240`, `LoginPage.tsx:65,128`.
